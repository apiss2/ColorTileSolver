# ColorTile Solver

カラータイルのスクリーンショットから盤面を読み取り、すべてのタイルを消すクリック手順を探す Windows 用アプリです。画面のボタンで操作する GUI 版と、コマンドで実行する CLI 版があります。画像認識と探索は C++17 で実装しています。

Windows の 64 ビット版は [GitHub Releases](https://github.com/apiss2/ColorTileSolver/releases/latest) からダウンロードできます。ソースコードはこのリポジトリで公開しています。

![画面例](examples/app_preview.png)

## ダウンロードと起動

1. [最新リリース](https://github.com/apiss2/ColorTileSolver/releases/latest) の `ColorTileSolver-1.1.0-windows-x64.zip` をダウンロードします。
2. ZIP をフォルダへすべて展開します。`examples/` も同じフォルダに残してください。
3. 展開先の `ColorTileSolver.exe` を起動します。Python や追加の C++ ランタイムのインストールは不要です。

Windows 10／11 の 64 ビット環境で使用できます。配布 ZIP には GUI 版と CLI 版のほか、サンプル、説明書、ライセンスを含みます。ソースからビルドする場合は、このリポジトリを取得し、後述のビルド手順に進んでください。

## できること

- PNG・JPEG・BMP などの画像から、タイルの位置と色を読み取ります。画像はドラッグ＆ドロップや `Ctrl+V` での貼り付けでも開けます。
- 読み取った色を手動で修正し、盤面の格子の位置や間隔を調整できます。
- 時間を決めて全消し手順を探すか、最も少ない手数だと確認できるまで探すかを選べます。
- 見つかった手順を一手ずつ確認したり、自動再生したりできます。再生間隔は 0.1～60.0 秒を 0.1 秒単位で指定でき、手順は CSV に保存できます。
- ゲーム画面の盤面を指定すると、全消し手順を探して自動でクリックします。次のクリック位置だけを光らせて、手動で進めることもできます。
- 盤面を `.ctb` ファイルに保存して読み込み直せます。CLI 版では探索結果を JSON に出力できます。

「自動再生」はアプリ内の盤面表示を進めます。ゲームを操作する場合は「画面を指定して自動操作」、クリック位置だけを表示する場合は「画面を指定して次の手を表示」を使います。

## ビルド

Windows でビルドするには、Windows 10／11 の 64 ビット環境と、C++17 に対応した **64 ビットの LLVM-MinGW または MinGW-w64** を用意します。

GCC を使う場合は、C++ の `std::thread`・`std::mutex` を利用できる POSIX スレッドモデル版を選んでください。古い Win32 スレッドモデル版では、これらの機能を使えないためビルドできません。MSVC でのビルドには対応していません。

### PowerShell スクリプトでビルド

コンパイラと、アイコンなどの Windows リソースを組み込む `windres` を `PATH` に追加し、リポジトリ直下で実行します。

```powershell
.\build_windows.ps1
.\ColorTileSolver.exe
```

GUI と CLI の実行ファイルをリポジトリ直下へ生成します。アプリの実行に Python は不要です。

### CMake でビルド

CMake 3.20 以上と MinGW-w64 の `g++`、`windres`、`mingw32-make` を `PATH` に追加して実行します。

```powershell
cmake -S . -B .build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build .build --parallel
.\.build\ColorTileSolver.exe
```

GUI で使うサンプル画像はビルド時に実行ファイルの隣へコピーされます。生成された実行ファイルやビルドフォルダは Git の管理対象外です。

Linux では CLI と共通処理のテストをビルドできます（GUI は Windows 専用）。

```bash
cmake -S . -B .build -DCMAKE_BUILD_TYPE=Release
cmake --build .build --parallel
./.build/ColorTileSolverCLI examples/sample.ctb --seconds 10 --threads 4 --output result.json
```

## 基本操作

1. 展開先、またはビルド先の `ColorTileSolver.exe` を起動します。
2. 「ファイル」→「画像を開く」でスクリーンショットを選びます。「サンプルを開く」でも動作を試せます。`Ctrl+O`、`Ctrl+V`、画像のドラッグ＆ドロップも使用できます。
3. 「盤面」→「元画像と格子を表示」で、認識した格子と画像の位置を確認します。
4. 必要に応じて「盤面」メニューの「盤面を修正」や「認識位置を調整」で認識結果を直します。
5. 探索モードと時間を設定し、「最短手順を探索」を押します。
6. 手順一覧、前後のボタン、自動再生でクリック位置を確認します。

認識が不確かなマスには橙色の枠が表示されます。盤面を修正すると、それまでの探索結果は破棄されます。

再生ボタンの隣にある「間隔」で、次の手へ進むまでの秒数を変更できます。既定は 0.6 秒です。上下の矢印で 0.1 秒ずつ変えるか、数値を直接入力してください。再生中の変更も反映されます。0.1～60.0 秒の範囲外、または 0.1 秒刻みでない値を入力すると、直前の有効な値に戻ります。

画像の読み込みや貼り付け、サンプルを開く操作、盤面の保存は「ファイル」メニューから行えます。盤面は `Ctrl+S` でも保存できます。

標準の盤面は 23 列 × 15 行です。列数と行数を手動で設定する場合は、それぞれ 1～32 マスを指定でき、タイルは最大 256 枚まで扱えます。盤面の端が空白だけの場合や、画像の一部が隠れている場合は、格子の位置が合っているか確認してください。

## ゲーム画面で使う

### 自動クリック

1. ゲームの 23 列 × 15 行の盤面全体が、他のウィンドウに隠れず表示されるようにします。
2. このアプリで探索モード、探索時間、下部の「間隔」を設定します。
3. 「画面を指定して自動操作」を押し、盤面全体を左上から右下へドラッグします。盤面の周りに少し余白を含めても認識できます。選択中は `Esc` または右クリックで取り消せます。
4. 全消し手順が見つかると、このアプリが最小化され、指定したゲームが前面になります。その盤面が認識した内容と一致することを確認して、自動クリックを開始します。
5. 全消しを画面上でも確認すると終了し、このアプリに戻ります。

途中で止めるには **Esc** を押します。F8 でも停止できます。アプリを前面に戻した場合も、ゲームが前面でなくなった時点で停止します。探索中は「画面操作を停止」または通常の「停止」でも中止できます。

自動クリックは各手の前に盤面を読み取り、クリック後に予定したタイルが消えたことを確認してから次へ進みます。設定した「間隔」より短い間隔ではクリックしません。ゲームの画面更新やその確認に時間がかかると、クリック間隔は設定値より長くなります。

クリック後の変化を 2 秒以内に確認できなければ停止します。同じクリックを送り直すことはありません。

### 次の手を光らせる

「画面を指定して次の手を表示」を押し、自動クリックと同じ方法で盤面を選びます。全消し手順が見つかると、ゲーム画面の次のクリック位置に黄色いリングが表示されます。

リングの上をクリックすると、その下のゲームへクリックが届きます。予定したタイルが消えたことをアプリが確認すると、次の位置へリングが移ります。このモードではアプリが自動でクリックすることはありません。終了方法は自動操作と同じです。

### 画面操作の条件

標準の配色の盤面を、通常のウィンドウ表示で使用してください。対象ウィンドウの移動やサイズ変更、ディスプレイ構成の変更、他のウィンドウによる遮蔽、前面ウィンドウの切り替えを検出すると停止します。

盤面が予定外の状態に変わった場合も停止します。タブの切り替えやスクロールで盤面が動いた場合は、読み取った盤面が予定した状態と一致しなくなれば停止します。再開するときは、盤面の範囲を指定し直してください。

色や格子の位置を確実に読み取れない場合や、一部のタイルしか消せない手順しか見つからなかった場合は、画面操作を開始しません。ゲーム側のアニメーションや終了表示で最後の盤面が隠れると、全消しを確認できずに停止することがあります。

全消し手順が見つかれば、最短性が未確認でも画面操作に使えます。その場合は、実行後も最短性が未確認であることを表示します。

ゲームとこのアプリは通常の権限で起動してください。管理者権限のゲーム、Windows が前面への切り替えや入力を拒否するウィンドウ、保護された画面への入力には対応していません。画面の読み取りと操作は PC 内で行い、取得した画像をネットワークへ送信しません。

## 探索結果の読み方

「時間を指定して探索」は、指定した時間内に見つかった全消し手順のうち、最も少ない手数のものを残します。既定は 10 秒で、0.1～86,400 秒を指定できます。

「最短確定まで探索」は時間制限を設けず、より短い全消し手順が存在しないことを確認するまで探します。途中で停止した場合も、それまでに見つかった手順を残します。

| 表示 | 意味 |
|---|---|
| 最短確定 | 全消しでき、これより少ないクリック数の手順がないと証明できました。 |
| 最短性未確認／全消し暫定解 | 全消しできますが、さらに少ない手数で消せる可能性があります。 |
| 時間内に全消し未発見 | 制限時間内に全消し手順が見つかりませんでした。全消しできないと証明したわけではありません。 |
| 全消し不能 | 認識した盤面には全消し手順がないと判定しました。盤面を正しく読み取れているかも確認してください。 |

最短の基準はクリック回数です。マウスの移動距離やゲームの操作時間を最も短くする探索ではありません。

「下界」は、全消しに少なくとも必要だと分かっているクリック数です。見つかった全消し手順の手数と下界が一致すれば、それより少ない手数では消せないため、最短だと確定できます。

大きな盤面では、全消し手順が見つかっても最短性の証明に時間がかかります。制限時間内に全消しや最短性の証明を必ず達成できる保証はありません。並列探索では同じ時間設定でも結果が変わる場合があります。

## コマンドライン版

配布 ZIP を使用する場合は、展開先のフォルダで実行します。

```powershell
.\ColorTileSolverCLI.exe .\examples\sample.ctb --seconds 10 --threads 4 --output result.json
```

CMake でビルドした場合は、リポジトリ直下で次のように実行します。

```powershell
.\.build\ColorTileSolverCLI.exe .\examples\sample.ctb --seconds 10 --threads 4 --output result.json
```

PowerShell スクリプトでビルドした場合は、配布 ZIP と同じ `.\ColorTileSolverCLI.exe` を使用します。`--seconds 0` を指定すると、時間を制限せずに探索します。

JSON の `status` が `optimal` の場合だけ、最短性が証明済みです。`feasible` は全消し手順が見つかったものの、最短性はまだ証明できていない状態です。行番号と列番号は 1 から数えます。

GUI から保存した CSV のクリック座標は、読み込んだ画像内の位置を表します。画面全体の座標ではありません。

`.ctb` は先頭に幅と高さ、続いてマスの色番号を並べたテキスト形式です。`0` は空白、`1`～`10` は順に灰・青・水色・緑・黄・茶・橙・赤・桃・紫です。具体例は [sample.ctb](examples/sample.ctb) を参照してください。

## テスト

以下のテストは、ソースを CMake でビルドしてから実行してください。

```powershell
ctest --test-dir .build --output-on-failure
```

独立した実装と探索結果を比べるテスト、3×3 盤面の全組合せなどを調べるテスト、画像認識に渡す値の検査、画面操作の手順照合テストを実行します。いずれも、実際のゲーム画面へクリックを送りません。

スクリーンショットの拡大縮小・余白・JPEG 圧縮などの認識テストには、追加で Python と Pillow が必要です。アプリの実行には不要です。

```powershell
python -m pip install Pillow
python tests/test_recognition.py --driver .build/test_recognition.exe
```

Linux ではドライバーのパスを `.build/test_recognition` に置き換えてください。

Windows GUI の起動・停止・手順移動・探索中の終了も、次のテストで確認できます。実行中はアプリのウィンドウが開きます。

```powershell
.\.build\test_gui_windows.exe "$PWD\.build\ColorTileSolver.exe" "$PWD\examples\sample.png"
```

画面操作のテストは、専用のゲームウィンドウを起動して実際のクリック入力を確認します。実行中はマウスと前面ウィンドウを操作するため、他の作業をしないテスト用デスクトップで実行してください。

```powershell
.\.build\test_desktop_windows.exe "$PWD\examples\sample.ctb"
.\.build\test_screen_gui_windows.exe "$PWD\.build\ColorTileSolver.exe" "$PWD\.build\test_desktop_windows.exe" "$PWD\examples\sample.ctb"
```

`test_live_playback` は、読み取った盤面と予定した状態が一致するか、クリック間隔を守るか、クリックに応答がなければ停止するか、手動操作後にヒントが進むかを調べます。実際の画面は操作せず、上記の `ctest` で実行されます。

過去の検証条件と結果は [検証レポート](docs/TEST_REPORT.md) を参照してください。実行環境や所要時間の記録は、その検証時点のものです。

## フォルダ構成

| パス | 内容 |
|---|---|
| `src/` | 探索・画像認識・CLI・Windows GUI とリソース。 |
| `tests/` | 参照探索との比較、画像認識、Windows GUI のテスト。 |
| `examples/` | サンプル画像、盤面データ（`.ctb`・JSON）と画面例。 |
| `docs/` | 検証レポート。 |
| `licenses/` | コンパイラ・実行時ライブラリのライセンス。 |
| `CMakeLists.txt` | アプリとテストのビルド定義。 |
| `build_windows.ps1` | Windows 用の簡易ビルドスクリプト。 |

実行ファイル、ライブラリ、アーカイブ、ビルド中間生成物はコミットしません。画像とアイコンはアプリのリソースおよびテスト入力として管理します。
